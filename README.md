# Т-Банк — мобильный интерфейс (React, frontend-only)

## Главная цель

Сделать **mobile-first сайт приложения Т-Банк с фокусом на UX/UI**: он должен
выглядеть и вести себя как реально работающее приложение банка — при том что
бэкенда нет и все данные захардкожены (`src/data/mock.js`).

Из этой цели следует всё остальное в этом файле:

- **Выглядит как рабочее приложение.** Никаких признаков прототипа: full-bleed,
  без рамки телефона, без нарисованного статус-бара, без галереи экранов.
  Видимых заглушек вместо контента быть не должно — карточка без обложки,
  пустая плашка или «рыбный» текст читаются как недоделка и бьют прямо в
  главную цель.
- **Ведёт себя как рабочее приложение.** Сеть не задействована, но интерфейс
  этого не показывает: любое действие доводится до логичного конца —
  переключение, подтверждение, переход на следующий экран или на свой же экран
  с обновлённым состоянием. Мёртвых кнопок нет.
- **UX связан целиком.** Переход с любого экрана ведёт туда, куда ожидается, и
  возвращается обратно без тупиков. Всё, что выглядит нажимаемым (кнопка, чип,
  строка списка, таб), на нажатие реагирует: открывает экран, переключает
  состояние или даёт видимый отклик.
- **UI единый.** Новые экраны и карточки собираются из тех же компонентов
  (`Screen`, `NavHeader`, `Row`, `QuickAction`, `BankCard` и т.д.) и токенов из
  `tokens.css`, а не копируют разметку с другими классами и отступами. Экран
  карты другого типа (как `CardPlatinum.jsx` для Black) строится по образцу
  существующего — те же секции, отступы, набор быстрых действий и анимации,
  различаются только данные и акцентный вариант компонента.
- **Анимации единые.** Все переходы состояний — открытие модалок, переключение
  табов, нажатия, появление/исчезновение элементов — используют один стиль
  (одинаковая длительность и кривая), а не разный для каждого экрана.

Технически это 22 экрана на React + Vite, frontend-only. Разбор UX/UI и импорт
в Figma — побочное применение того же результата, а не цель, под которую можно
упрощать интерфейс.

## Запуск

```bash
npm install          # один раз
npm run dev          # http://localhost:5173
npm run build        # сборка в dist/
npm run preview      # посмотреть собранное
```

Открыть на телефоне в одной Wi-Fi сети: `npm run dev -- --host`, затем перейти
по адресу из строки Network.

## Mobile first

Главный брейкпоинт — **iPhone 15: 393 × 852 CSS px**. Вёрстка не фиксирует
ширины, поэтому без отдельного кода тянется на все айфоны от SE (375) до
Pro Max (430). Десктопной версии нет сознательно.

Учтены `env(safe-area-inset-*)` и `100dvh` — иначе панель Safari срезает низ
экрана, а таб-бар наезжает на домашний индикатор.

## Выписка и движение средств

`/statement` — выписка по счёту Black: история операций с пресетами периода —
месяц, 3 месяца, полгода, год. Этот экран заменил прежнюю «Историю»
(`/history`): та показывала одну неделю операций и вписанные в разметку итоги,
а поиск, фильтры и «Показать ещё» на ней не работали. Все входы, которые вели
в историю — карточка «Все операции» на главном, «Вся история» на экранах карт,
кнопка выписки на «Расходах» и строка в профиле, — ведут сюда. Период — целые календарные месяцы, последний неполный: «Месяц»
это ноябрь по сегодняшний день. Так столбики по месяцам сходятся с итогами
один в один; при скользящем окне в период попадал бы хвост тринадцатого
месяца, которому неоткуда взяться на графике из двенадцати столбиков.

Данные — реальная выписка по счёту Black · 7711 с 12 ноября 2025 по
10 ноября 2026, 148 операций, в `data/ledger.js`. Раньше текущий месяц
описывался в `mock.js` поштучно, а год до него собирал генератор
`data/archive.js`; теперь источник один, и `operations` — это просто срез
леджера по текущему месяцу. Контрольные суммы выписки сходятся с тем, что
считает экран: поступления 6 003 290,00 ₽, расходы 2 403 108,85 ₽.

Зарплата приходит 5-го числа, аванс — 20-го, трижды за период добавляется
квартальная премия. Кэшбэка в выписке нет — он считается по ставке категории
(продукты, рестораны и маркетплейс 5%, аптека 3%, техника 2%), иначе экраны
кэшбэка и бонусов остались бы пустыми.

Итоги, столбики и разбивка по категориям считаются из операций
(`lib/period.js`), а не вписаны в разметку. На тех же расчётах работают
«Расходы» и карточка трат на главном: раньше и они, и «История» показывали за
месяц выдуманные 48 230 ₽, не сходившиеся ни с одной операцией.

Кнопка «Сохранить в PDF» открывает шторку запроса на почту
(`components/EmailSheet.jsx`): адрес, проверка на явную опечатку, затем
подтверждение. Этой же шторкой запрашиваются правовые документы в профиле —
один компонент на оба входа, а не копия, иначе две одинаковые на вид шторки
со временем разошлись бы в поведении и в текстах.

Шестерёнка справа от пресетов открывает шторку «Период выписки» с календарём
(`components/Calendar.jsx`): первое нажатие задаёт начало, второе — конец,
дата раньше начала начинает выбор заново. Листать дальше данных нельзя, дни
в будущем недоступны: границы — 12 ноября 2025 и «сегодня», константы `DATA_FROM`
и `DATA_TO`. Выбор применяется кнопкой, а не на лету, иначе половина диапазона
пересчитывала бы экран под руками.

Даты внутри календаря — строки `'YYYY-MM-DD'`, а не `Date`: операции хранят
дату строкой, сравнение строк даёт тот же порядок, и 1 ноября не превращается
в 31 октября из-за часового пояса.

Применённый период встаёт пятым чипом в тот же ряд и подсвечивается: иначе
было бы непонятно, за что показаны цифры, когда ни один пресет не активен.
Следующий выбор заменяет этот чип, а не копит их.

«Сохранить в PDF» и кнопка отправки в шапке открывают одну и ту же шторку
(`Sheet`, как выбор счёта в переводах): ввод почты, кнопка «Запросить» — она
неактивна, пока адрес не похож на адрес, — и дальше та же шторка показывает
подтверждение с зелёной галочкой `status-badge`, как экран успешного перевода.
Письма, разумеется, никто не шлёт: бэкенда нет.

Перевод на свой накопительный счёт входит в «Расходы» (деньги со счёта ушли),
но не попадает в «Траты по категориям»: это перекладывание, а не покупка,
и в октябре он один забирал 59% диаграммы.

Строка списка (`Row`) — один компонент на продукты, операции, настройки и
активы: меняются только плашка слева и правая часть. Иконки — инлайновые SVG
на `currentColor`, в Figma приезжают векторами.

## Картинки слайдеров

Обложки офферов лежат в `public/img/`, квадратные арты сторис — в
`public/image/`. И те и другие подключаются полем `cover` в
`src/data/mock.js`. Пока файла нет, карточка показывает градиентную
подложку с подписью — экран не ломается. Список ожидаемых имён файлов
и размеров — в `public/img/README.md`.

## Проверка вёрстки

```bash
npm run preview                  # в одном терминале
node scripts/shots.mjs           # в другом
```

Скрипт снимает экраны из списка `ROUTES` в настоящей эмуляции iPhone 15
(393 × 852, DPR 3) и проверяет, что нет горизонтального выезда. Список отстаёт
от `App.jsx`: `/bills`, `/regular`, `/between`, `/topup` и `/more/:id` пока не
снимаются. Он нужен, потому что headless
Chrome не открывает окно уже 500px — без эмуляции устройства главный
брейкпоинт проверить нечем. Скриншоты кладутся в `screenshots/`.

## Публикация на GitHub Pages

Автодеплой не настроен — по договорённости. Содержимое `dist/` после
`npm run build` готово к публикации как есть: `base: './'` в `vite.config.js`
делает сборку работоспособной в подпапке вида
`https://<user>.github.io/<repo>/`.

## Импорт в Figma

Поднять сервер (`npm run preview`) и скармливать плагину html.to.design адреса
вида `http://localhost:4173/#/home` — по одному экрану. Токены из
`src/styles/tokens.css` переносятся в переменные Figma один к одному.

## Оговорки

Бэкенда нет по условию задачи: все данные захардкожены в `src/data/mock.js`.
Это ограничение реализации, а не оправдание для интерфейса — см. «Главная
цель»: снаружи приложение должно выглядеть работающим.

Шрифт — системный (`-apple-system`, то есть SF Pro на iPhone и Mac). В самом
приложении интерфейсный текст набран им же: цифры в карточках совпадают по
рисунку с часами в статус-баре, которые рисует iOS. Inter остаётся запасным
для платформ без SF Pro.

Фирменный Tinkoff Sans (ныне T-Bank Sans) здесь не используется: он
собственность TCS Group и без письменного разрешения применяться не может.
В прототипе он встречается только внутри готовых артов сторис, где текст
вшит в картинку. Айдентика воспроизведена для учебного разбора, это не
продукт банка.
